OPERATION ANANSI

SUBJECT: Real-Time Regional Intelligence Dashboard — Hampton Roads / Historic Triangle (757 / 804)
01 // MISSION BRIEF

Overview

Anansi is a self-hosted, real-time geospatial dashboard covering the Hampton Roads / Historic Triangle region of Virginia. It fuses a self-hosted n8n automation server as the intelligence ingestion layer with God's Eye View, an open-source CesiumJS 3D globe platform, to render live public data — traffic, weather, local news — as a single operational picture.

Objective: build something closer to a lightweight SOC-style situational awareness tool than a static map. Multiple independent feeds, normalized into one schema, polled continuously, rendered without manual refresh.

02 // FIELD LOG

Operational Timeline

ENTRY 001 — INFRASTRUCTURE

Environment Setup

Base platform deployed locally on Windows 11 (Node.js/Vite). Docker Desktop required for the automation layer — required enabling virtualization in BIOS, disabled by default.

ENTRY 002 — AUTOMATION

Self-Hosted Automation Server (n8n)

n8n deployed as a Docker container, persisting workflow data in a named volume. Each data source runs its own workflow, triggered on-demand by webhook rather than a fixed schedule — upstream APIs are only queried when the dashboard is actively being observed.

ENTRY 003 — TRAFFIC INTEL

Traffic Data Pipeline

Live incident data pulled from TomTom's Traffic Incident Details API (v5), bounded to Norfolk, Virginia Beach, Chesapeake, Portsmouth, Suffolk, Newport News, and Hampton. Normalized into a consistent {lat, lng, label, type, metadata} schema. Beyond static incidents, the TomTom flow API drives a live vehicle-tracking overlay — individual moving markers on real Williamsburg-area streets, continuously updating.

ENTRY 004 — WEATHER INTEL

Weather Alerts Pipeline

NOAA's public Alerts API required no key, but a descriptive User-Agent header — omission returns a silent 403, an under-documented requirement. Alerts are zone-based rather than coordinate-based, so a lookup table maps known localities to approximate coordinates.

ENTRY 005 — LOCAL NEWS INTEL

Local News Pipeline — Historic Triangle

Original plan targeted a Williamsburg news outlet's RSS feed directly — the source actively blocks automated requests at the network level, returning 403 regardless of headers. Pivoted to a location-filtered Google News RSS query, requiring a raw regex-based XML parser rather than n8n's built-in conversion node, whose actual output shape didn't match documented behavior. Obituary and real-estate listing noise filtered at parse time.

ENTRY 006 — INTEGRATION

Hampton Roads 757 Panel — Built, Then Redesigned

Originally built as a Cesium map layer polling all three n8n webhooks, rendering colored dots on the globe. A real bug surfaced early: a single failed poll on enable was reverting the entire toggle to OFF ("could not start cleanly") instead of degrading gracefully — fixed so the layer stays on and retries automatically instead of failing hard.

A Hampton Roads (757) location pill was added with five real landmarks (Nauticus, Virginia Beach Oceanfront, the Bridge-Tunnel, Naval Station Norfolk, Chrysler Museum), and every other preset city pill was hidden from the UI without deleting its underlying data — CCTV and voice control still reference it under the hood.

Final redesign: pulled out of the data-layer system entirely. No more map dots, no ON/OFF toggle in Data Layers — it now lives as a persistent panel on the right rail, a live-scrolling feed of real traffic incidents, weather alerts, and news headlines, each carrying source, severity, and timestamp.

ENTRY 007 — COVER IDENTITY

Rebrand: Anansi

Base platform rebranded end-to-end — UI, page title, and config/branding strings (AI prompts, User-Agent headers, console messages); project docs and the original repo/YouTube links were left untouched since those describe the real public source. Logo replaced everywhere — favicon, title bar, loading screen — with an original red spider-mark SVG. Full color pass: black/near-black backgrounds, gold text (#d4af37 primary, #a8842a dimmer for secondary/hint text — both verified against WCAG contrast at 9.4:1 and 5.6:1), red (#c81e1e) for buttons, borders, and active states. A follow-up pass caught several spots the first sweep missed: icon SVGs with colors baked directly into the file rather than driven by CSS, the voice-control widget's waveform, the first-run modal, command-dock borders, CCTV panel indicators. Subtitle changed to "I'm everywhere. And nowhere."

ENTRY 006B — NETWORK DEBUGGING

Live Vehicle Tracking — TomTom Activation & a Real Debugging Chain

Separate from the n8n incident pipeline, the base platform's own native TOMTOM_API_KEY — sitting commented-out in .env — was activated to drive live vehicle-position tracking directly on the globe. What followed was diagnosing "traffic won't populate / stuck at 0% coverage," which turned out to have three distinct, unrelated root causes rather than one:

1. Norton Antivirus's SSL inspection. Its own certificate wasn't trusted by Node, causing intermittent UNABLE_TO_VERIFY_LEAF_SIGNATURE failures on any outbound HTTPS call. Fixed by pointing NODE_EXTRA_CA_CERTS at Norton's own auto-maintained certificate bundle, set as a persistent machine-level environment variable (not committed to the repo — machine-specific).

2. Overpass mirror ordering. The first-tried mirror (overpass-api.de) was hard-hanging at the TCP level, burning the full 22-second timeout before ever reaching a working mirror. Fixed by reordering the mirror list to try working ones first.

3. A second, unrelated bug: the Overpass proxy's User-Agent was a stale pre-rebrand string (gods-eye-view-overpass-proxy/1.0) that overpass-api.de's abuse filter was hard-blocking with a 406 on every request — nothing to do with Norton at all. Proven by swapping only that header in isolation; fixed to Anansi/1.0.

Cause-level logging was added to both proxies (vite.config.js) so any future failure surfaces the actual reason instead of a bare "fetch failed." A live firewall-off test confirmed Norton's firewall itself wasn't the remaining blocker — TomTom behaved identically either way, and the stale User-Agent was the actual missing piece for Overpass.

End state, confirmed live in-session: TomTom flow, Overpass road geometry, and the Hampton Roads panel all running on real data — 98+ live traffic incidents, real news headlines, clean coverage percentages instead of stuck zeros.

04 // OBSTACLES ENCOUNTERED

Debrief: Complications in the Field

  • Norton Antivirus's SSL inspection — its own certificate wasn't trusted by Node, causing intermittent UNABLE_TO_VERIFY_LEAF_SIGNATURE failures on outbound HTTPS calls. Not a firewall issue — confirmed by testing with the firewall fully disabled and seeing identical behavior. Fixed via NODE_EXTRA_CA_CERTS pointed at Norton's own certificate bundle.
  • Overpass mirror hanging at the TCP level — the first-tried mirror consumed the entire 22-second timeout before ever reaching a working one, masquerading as a total failure when only one mirror was actually broken.
  • A stale pre-rebrand User-Agent silently 406'd by Overpass's abuse filter — looked identical to the mirror-timeout symptom from the outside, isolated only by swapping the header alone and re-testing.
  • NOAA's undocumented User-Agent requirement — a silent 403 with no indication of cause until cross-referencing NOAA's own documentation directly.
  • Source-level bot blocking — the original news source's protection couldn't be bypassed with header spoofing, forcing a full pivot to a different feed.
  • n8n's XML node output shape — didn't match assumed conventions three separate times; resolved by dumping the raw HTTP response and parsing the actual structure directly.
  • n8n's empty-array execution behavior — a workflow returning zero results (a valid state) silently halted execution before the response node, requiring the "Always Output Data" setting to be explicitly enabled.
  • A layer-level failure mode — one failed poll on enable was reverting the entire Hampton Roads toggle to OFF rather than degrading gracefully; fixed to retry automatically instead of failing hard.
  • Google Cloud billing — the Photorealistic 3D Tiles API requires a linked payment method even for free-tier usage; blocked the optional Google 3D imagery layer. Logged as an open item.

Three of the traffic-related failures above looked identical from the outside — all presented as "coverage stuck at 0%." Isolating them required changing one variable at a time (firewall off/on, header swap, mirror order) rather than assuming a single cause.
